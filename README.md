# 3D-RPG
Unity 기반 3D RPG 멀티플레이 게임입니다.  

`ScriptableObject`와 `JSON`을 활용해 캐릭터, 아이템, 퀘스트 데이터를 분리 관리했으며,  
`Photon`을 사용해 멀티플레이 환경을 구현했습니다.  

`Firebase`를 연동하여 유저 정보와 저장 데이터를 관리하고,  
`Jenkins`를 활용한 자동 빌드 환경을 구성해 수정 사항 반영 후 빌드 과정을 안정적으로 관리할 수 있도록 했습니다.

## 주요 기능
- 3D 플레이어 이동 / 전투 시스템 — 캐릭터 이동, 공격, 몬스터 전투 구현
- NPC / 퀘스트 시스템 — 상점, 업그레이드, 퀘스트 수락, 진행, 완료 흐름 구현
- 인벤토리 / 아이템 시스템 — 아이템 획득, 장착, 판매 기능 구현
- 데이터 관리 시스템 — `ScriptableObject`와 `JSON`으로 캐릭터, 아이템, 퀘스트 데이터 분리
- `Photon` 멀티플레이 — 플레이어 생성, 상태 동기화, 몬스터 AI 동기화 구현
- `Firebase` 저장 시스템 — 유저 인증 및 플레이어 데이터 저장
- `Jenkins` 자동 빌드 — 수정 사항 반영 후 자동 빌드 환경 구성

## 기술적 고민
### 1. `Photon` 기반 멀티플레이 동기화
- 여러 플레이어가 같은 방에 접속했을 때 플레이어와 몬스터 상태가 동일하게 유지되도록 동기화 구조를 구성했습니다.
- `Master Client` 기준으로 몬스터 생성과 주요 상태를 관리하고, `PhotonView / RPC / RaiseEvent`를 활용해 클라이언트 간 상태를 전달했습니다.
- `Late Join` 상황에서도 기존 게임 상태를 받을 수 있도록 처리하여 참가자 입장 후 상태 차이를 줄였습니다.
### 2. `ScriptableObject / JSON` 기반 확장성 개선
- 캐릭터, 아이템, 퀘스트 데이터가 코드에 직접 묶이지 않도록 `ScriptableObject`와 `JSON`으로 데이터를 분리했습니다.
- 정적인 게임 데이터는 `ScriptableObject`로 관리하고, 유저 진행 상태와 저장 데이터는 `JSON`으로 저장했습니다.
- 데이터와 로직을 분리하여 새로운 아이템이나 퀘스트를 추가할 때 코드 수정 부담을 줄였습니다.
### 3. 3D 환경 성능 최적화
- 3D 오브젝트와 이펙트가 늘어나면서 발생할 수 있는 렌더링 부하를 줄이기 위해 최적화를 진행했습니다.
- `Static 설정, Occlusion Culling, LOD, Sprite Atlas`를 적용하여 불필요한 렌더링 비용을 줄였습니다.
- `Profiler`를 활용해 성능 병목 구간을 확인하며 3D 환경에서 더 안정적인 플레이가 가능하도록 개선했습니다.

## 회고
3D RPG에 멀티플레이를 적용하면서 플레이어, 몬스터, 게임 상태를 클라이언트 간 일관되게 유지하는 것이 가장 어려웠습니다.  
`Photon`을 활용해 `Master Client` 기준으로 주요 상태를 관리하고, `Late Join` 상황까지 고려하면서 멀티플레이 동기화 구조의 중요성을 경험했습니다.

또한 캐릭터, 아이템, 퀘스트 데이터를 `ScriptableObject`와 `JSON`으로 분리하며 기능 확장에 유리한 데이터 구조를 고민할 수 있었습니다.  
3D 환경에서는 `Profiler`를 통해 렌더링 비용을 확인하고, `Static 설정, Occlusion Culling, LOD, Sprite Atlas` 등을 적용하며 성능 최적화 흐름을 익혔습니다.

마지막으로 `Jenkins` 자동 빌드 환경을 구성하면서 반복적인 수동 빌드 과정을 줄이고, 프로젝트 수정 사항을 더 안정적으로 빌드에 반영하는 경험을 했습니다.
